# leafer-free-board 新架构文档

> 版本：v1.2 · 2026-07-22  
> 目标：单 npm 包发布，对外提供**可编辑画板**与**渲染画板**两种模式；全局共享一个 Leafer `App` 实例；工具能力通过**插件注入**扩展；数据通过**快照参数**驱动预览。

---

## 0. 命名约定

为避免 `Board` 一词在类名、文件名、inject key 中重复出现且语义模糊，统一采用以下命名域：

| 命名域 | 含义 | 示例 |
|--------|------|------|
| **App** | Leafer 原生引擎实例 | `app.tree`、`app.editor` |
| **EditorCore** | 编辑器控制器（插件、历史、快照、CRUD） | `EditorCore.use()`、`editor.history` |
| **Canvas** | 画板实例域（Context、组件、快照、运行态） | `CanvasContext`、`EditorCanvas` |
| **Engine** | 画板引擎容器层（编辑 / 渲染 Vue 容器） | `engine/edit`、`engine/render` |
| **CanvasMode** | 运行时枚举 `edit \| render`（非目录名） | `CanvasContext.mode` |
| **Snapshot** | 可序列化的画布数据 | `ICanvasSnapshot` |

**刻意不使用 `Board` 参与 API 命名**（如 ~~BoardContext~~、~~RenderBoard~~、~~IBoardSnapshot~~）。  
目录 **`engine/`** 表示「画板引擎容器层」（编辑 / 渲染对外 Vue 组件），与运行时枚举 **`CanvasMode`**（`edit | render`）区分，不再使用 ~~`modes/`~~ 作为目录名。  
npm 包名 `@leafer-free/board` 可保留（与仓库名一致），对外导出的类型与组件以 **Canvas / EditorCore / Engine** 为准。

**现有代码迁移对照**：

| 旧名（文档 v1.0 / 现有代码） | 新名 |
|------------------------------|------|
| `EditorBoard`（类） | `EditorCore` |
| `BoardContext` | `CanvasContext` |
| `BoardFactory` | `CanvasFactory` |
| `EditorBoard.vue` | `EditorCanvas.vue` |
| `RenderBoard.vue` | `RenderCanvas.vue` |
| `modes/`（目录，已废弃） | `engine/` |
| `BoardProvider` | `CanvasProvider` |
| `IBoardSnapshot` | `ICanvasSnapshot` |
| `BoardMode` | `CanvasMode` |
| `saveBoard` / `loadBoard` | `saveSnapshot` / `loadSnapshot` |
| `useBoardContext` | `useCanvasContext` |
| `useEditorBoard` | `useEditorCore` |
| `useBoardSnapshot` | `useCanvasSnapshot` |
| `inject("editorBoard")` | `useEditorCore()` |

## 1. 设计目标

| 目标 | 说明 |
|------|------|
| **单包发布** | 只发布一个 npm 包 `@leafer-free/board`（包名可保留，API 用 Canvas 命名），不拆多包 |
| **双引擎容器** | `EditorCanvas`（编辑）+ `RenderCanvas`（渲染/预览），位于 `engine/`，共享同一套 Core |
| **全局单 App** | 每个画板实例内，`App` 与 `EditorCore` 由 `CanvasContext` 统一管理，避免多处 `new App()` |
| **插件注入** | 编辑能力（吸附、标尺、快捷键等）以插件形式按需 `use()`，渲染模式默认不加载 |
| **参数驱动预览** | 渲染画板通过 `snapshot` props 传入画布 JSON，无需编辑器插件 |
| **易扩展** | 新增工具 = 新增 Plugin；新增 UI = 新增 Component + inject |
| **易维护** | Core / Plugin / UI / Engine 四层分离，职责单一 |

              │  │  · mode: edit | render │  │
              │  └────────────────────────┘  │
              └──────────────┬───────────────┘
                             ▼
              ┌──────────────────────────────┐

## 4. 核心模块设计

### 4.1 CanvasContext — 全局画板对象域

每个画板组件实例对应**一个** `CanvasContext`，内部持有唯一的 `App` 与 `EditorCore`：

```typescript
// core/CanvasContext.ts
import type { App } from "leafer-ui";
import EditorCore from "./EditorCore";
import { CanvasFactory } from "./CanvasFactory";
import type { ICanvasSnapshot, CanvasMode, IAppConfig, IPluginTempl, IPluginOption } from "./types";

export class CanvasContext {
  readonly mode: CanvasMode;           // "edit" | "render"
  readonly app: App;
  readonly editor: EditorCore;

  constructor(options: {
    view: HTMLElement;
    mode: CanvasMode;
    appConfig?: Partial<IAppConfig>;
  }) {
    this.mode = options.mode;
    this.app = CanvasFactory.createApp(options.view, options.mode, options.appConfig);
    this.editor = new EditorCore();
    this.editor.init(this.app);
  }

  /** 从快照加载（编辑/渲染共用） */
  loadSnapshot(snapshot: ICanvasSnapshot) {
    this.editor.loadSnapshot(snapshot);
  }

  /** 导出快照（仅编辑模式常用） */
  saveSnapshot(): ICanvasSnapshot {
    return this.editor.saveSnapshot();
  }

  /** 注册插件 — 工具注入入口 */
  use(plugin: IPluginTempl, options?: IPluginOption) {
    this.editor.use(plugin, options);
    return this;
  }

  destroy() {
    this.editor.destroy();
  }
}
```

**要点**：

- 不在组件、Store、Plugin 内各自 `new App()`，统一由 `CanvasContext` 创建。
- `EditorCore` 作为业务门面：`use()`、`history`、`saveSnapshot()`、`loadSnapshot()`。
- 渲染模式同样走 `CanvasContext`，但不挂载 editor 相关插件。

### 4.2 CanvasFactory — 按模式创建 App

```typescript
// core/CanvasFactory.ts
export const CanvasFactory = {
  createApp(view: HTMLElement, mode: CanvasMode, overrides?: Partial<IAppConfig>): App {
    const base = mode === "edit" ? EDIT_APP_CONFIG : RENDER_APP_CONFIG;
    return new App({ view, ...merge(base, overrides) });
  },
};
```

| 配置项 | edit 模式 | render 模式 |
|--------|-----------|-------------|
| `tree.type` | `"design"`（空格拖动画布） | `"viewport"` 或 `"design"`（可配置） |
| `editor` | 完整编辑手柄 | **不启用** 或 `visible: false` |
| Leafer 插件 side-effect | `@leafer-in/editor` 等 | 仅 `@leafer-in/viewport` 等只读依赖 |
| 默认插件 | Handler + Shape + Snap… | 无 / 仅 Viewport |

### 4.3 EditorCore — 编辑器控制器（原 EditorBoard）

由现有 `EditorBoard` 迁移并重命名，继续承担：

- 插件注册与 API 代理（`use`、`pluginMap`、hotkeys）
- 元素 CRUD（`addLeaferElement`、`removeLeaferElement`、`getById`）
- 历史记录（`HistoryManager`）
- 快照序列化（`saveSnapshot` / `loadSnapshot`，原 `saveBoard` / `loadBoard`）
- 事件总线（`EventEmitter`：`history:change`、`CustomEvent.*`）

插件构造函数参数建议统一为 `editor: EditorCore`（原 `editorBoard`）：

```typescript
class HandlerPlugin implements IPluginTempl {
  constructor(public editor: EditorCore) { /* ... */ }
}
```

## 5. 依赖注入机制

### 5.1 Vue 层：provide / inject

```typescript
// core/constants/injection-keys.ts
import type { InjectionKey } from "vue";
import type { CanvasContext } from "../CanvasContext";

export const CANVAS_CONTEXT_KEY: InjectionKey<CanvasContext> = Symbol("CanvasContext");
```

```vue
<!-- engine/shared/CanvasProvider.vue -->
<script setup lang="ts">
import { provide, onBeforeUnmount } from "vue";
import { CanvasContext } from "@/core/CanvasContext";
import { CANVAS_CONTEXT_KEY } from "@/core/constants/injection-keys";

const props = defineProps<{ mode: CanvasMode; plugins?: IPluginTempl[] }>();
const canvasRef = useTemplateRef("canvasRef");
let ctx: CanvasContext;

onMounted(() => {
  ctx = new CanvasContext({ view: canvasRef.value!, mode: props.mode });
  props.plugins?.forEach(p => ctx.use(p));
  provide(CANVAS_CONTEXT_KEY, ctx);
});

onBeforeUnmount(() => ctx?.destroy());
</script>
```

```typescript
// composables/useCanvasContext.ts
export function useCanvasContext() {
  const ctx = inject(CANVAS_CONTEXT_KEY);
  if (!ctx) throw new Error("[Canvas] 请在 EditorCanvas / RenderCanvas 内使用");
  return ctx;
}

// composables/useEditorCore.ts
export function useEditorCore() {
  return useCanvasContext().editor;
}
```

**现有组件改造**：将 `props.editor` / `inject("editorBoard")` 统一为 `useEditorCore()`。

### 5.2 插件层：EditorCore.use()

插件是**能力注入**的主要方式：

```typescript
class SnapPlugin implements IPluginTempl {
  static pluginName = "SnapPlugin";
  static apis = ["toggleSnap"];
  static hotkeys = ["alt+s"];

  constructor(public editor: EditorCore, public options: IPluginOption) {
    // 初始化 leafer-x-easy-snap
  }

  toggleSnap(enabled: boolean) { /* ... */ }
  destroy() { /* 清理 */ }
}
```

**插件契约**（沿用现有 `IPluginTempl`）：

| 静态字段 | 作用 |
|----------|------|
| `pluginName` | 唯一标识，防重复注册 |
| `apis[]` | 代理到 `editor.xxx()` |
| `hotkeys[]` | 通过 hotkeys-js 绑定 |
| `events[]` | 声明自定义事件，防冲突 |
| `destroy()` | 卸载清理 |

**默认插件装配**：

```typescript
// engine/edit/default-plugins.ts
export const DEFAULT_EDIT_PLUGINS = [
  HandlerPlugin,
  SnapPlugin,
  RulerPlugin,
  ScrollBarPlugin,
  DotMatrixPlugin,
  DeleteHotKeyPlugin,
  CopyPlugin,
  HistoryHotKeyPlugin,
  ShapePlugin,
] as const;
```

消费方可覆盖：

```vue
<EditorCanvas :plugins="[...DEFAULT_EDIT_PLUGINS, MyCustomPlugin]" />
```

## 6. 双引擎容器 API

> `engine/edit` 与 `engine/render` 分别承载**可编辑画板**与**渲染画板**的 Vue 容器，内部通过 `CanvasProvider` 创建 `CanvasContext`，对外暴露 props / events / slots。

### 6.1 EditorCanvas — 可编辑画板容器

```vue
<template>
  <EditorCanvas
    v-model:snapshot="canvasData"
    :auto-save="true"
    :storage-key="'my-canvas'"
    :plugins="defaultPlugins"
    @change="onCanvasChange"
    @ready="onReady"
  >
    <!-- 可选：插槽扩展工具栏 -->
    <template #toolbar-left><MyLogo /></template>
  </EditorCanvas>
</template>
```

| Prop | 类型 | 说明 |
|------|------|------|
| `snapshot` | `ICanvasSnapshot` | v-model 双向绑定画布数据 |
| `plugins` | `IPluginTempl[]` | 额外/覆盖插件列表 |
| `autoSave` | `boolean` | 是否防抖自动持久化 |
| `storageKey` | `string` | localStorage 键名 |
| `appConfig` | `Partial<IAppConfig>` | 覆盖 Leafer App 配置 |

| Event | 说明 |
|-------|------|
| `ready` | `(ctx: CanvasContext) => void` 初始化完成 |
| `change` | 画布数据变更（含 history） |
| `history:change` | 撤销栈状态变化 |

| Slot | 说明 |
|------|------|
| `toolbar-left` / `toolbar-right` | 扩展工具栏 |
| `attributes` | 替换属性面板 |

### 6.2 RenderCanvas — 渲染 / 预览画板容器

```vue
<template>
  <RenderCanvas
    :snapshot="previewData"
    :interactive="false"
    :fit-view="true"
    width="100%"
    height="480px"
  />
</template>
```

| Prop | 类型 | 说明 |
|------|------|------|
| `snapshot` | `ICanvasSnapshot \| ICanvasSnapshot['canvas']` | **核心**：画布 JSON，支持热更新 |
| `interactive` | `boolean` | 是否允许缩放/平移（默认 true） |
| `fitView` | `boolean` | 挂载后自动 fit 视口 |
| `plugins` | `IPluginTempl[]` | 可选，如 `ViewportPlugin` |
| `appConfig` | `Partial<IAppConfig>` | 渲染专用 App 配置 |

**行为差异**：

- 不加载 `@leafer-in/editor`、不注册 Shape / Copy / Delete 等编辑插件。
- 不渲染 ToolBar、ElementAttributes（除非通过 slot 自定义）。
- `snapshot` 变化时调用 `editor.loadSnapshot()` 或增量 diff（后期优化）。
- 不写入 history，不触发 autoSave。

### 6.3 编辑 → 预览的数据流

```
EditorCanvas               RenderCanvas
    │                           ▲
    │  saveSnapshot()           │  props.snapshot
    ▼                           │
 ICanvasSnapshot  ──保存/传输──►  loadSnapshot()
    │
    ├─ canvas: IUIJson[]
    ├─ connections: ISerializedConnection[]
    ├─ history: { undoStack, redoStack }   ← 渲染模式可忽略
    ├─ version: number
    └─ timestamp: number
```

## 8. 扩展指南

### 8.1 新增工具插件

1. 在 `plugins/edit/` 或 `plugins/render/` 新建 `XxxPlugin.ts`，实现 `IPluginTempl`。
2. 在 `plugins/index.ts` 导出。
3. 编辑模式：加入 `DEFAULT_EDIT_PLUGINS` 或由消费方 `:plugins` 传入。
4. 若需 UI：在 `components/` 新增面板，内部 `useEditorCore()` 调用 `editor.xxx()`。

### 8.2 新增图形类型

1. 在 `utils/creatElement.ts` 增加创建函数。
2. 在 `ShapePlugin` 或工具栏配置 `toolBar.ts` 注册 type。
3. 历史命令复用 `ExecuteTypeEnum.AddElement`，无需改动 HistoryManager。

### 8.3 自定义属性面板

```vue
<EditorCanvas>
  <template #attributes="{ editor }">
    <MyAttributesPanel :editor="editor" />
  </template>
</EditorCanvas>
```

### 8.4 渲染模式扩展交互

如需「预览但可点击热点」：

- 使用 `RenderCanvas` + `interactive=true` + 自定义 `RenderHitPlugin`。
- 在插件内监听 `app.tree` 的 `PointerEvent.TAP`，不引入 editor 模块。

## 9. 状态与存储边界

| 状态类型 | 存放位置 | 说明 |
|----------|----------|------|
| 画布元素树 | Leafer `app.tree` | 唯一渲染数据源 |
| 连线关系 | Plugin 内存 + snapshot.connections | HandlerPlugin 维护 |
| 撤销/重做 | `HistoryManager` | 仅 edit 模式 |
| UI 状态（当前工具、选中项） | 组件内 ref 或 Pinia（可选） | 不进入 snapshot |
| 持久化 | `useCanvasSnapshot` + localStorage / API | 业务层决定 |

**原则**：Pinia Store 不再持有 `App` 实例；Store 仅存 `ICanvasSnapshot` 或业务元数据。

## 11. 架构约束（团队约定）

1. **禁止**在 Plugin / Component 内直接 `new App()`，必须通过 `CanvasContext`。
2. **禁止** RenderCanvas 依赖 `@leafer-in/editor` side-effect import。
3. **所有**破坏性操作必须走 `editor.history.execute()`，保证可撤销。
4. **插件**必须实现 `destroy()`，并在 `EditorCore.destroy()` 链路上调用。
5. **对外**稳定 API 以 `ICanvasSnapshot`、`CanvasContext`、`IPluginTempl` 为准；内部重构不影响 snapshot 版本兼容。
6. **snapshot.version** 升级时提供迁移函数 `migrateSnapshot(v1 → v2)`。
7. **命名**新增 API 不得再引入 `Board` 前缀；历史别名可在过渡期通过 `deprecated` 导出兼容。

## 13. 总结

新架构以 **`CanvasContext`（单 App + 单 EditorCore）** 为中枢，以 **插件 `use()`** 注入工具能力，以 **`ICanvasSnapshot`** 连通编辑与渲染；**`engine/`** 层提供 `EditorCanvas` / `RenderCanvas` 两个对外容器。对外仅一个 npm 包，Core / Plugin / UI / Engine 解耦，命名清晰、便于长期维护与按需扩展。

当前仓库已具备约 **70%** 核心能力（EditorBoard → EditorCore、History、Plugins、Snapshot），主要工作是**目录重组、CanvasContext 抽象、RenderCanvas 新增、命名统一、npm 构建配置**，无需重写业务逻辑。
